Estado: PARCIALMENTE IMPLEMENTADO SEGUN PROCESAMIENTO HISTORICO D01-D04
Fecha: 2026-10-05

Objetivo
---------
Este documento registra decisiones que la evidencia del PDF no resuelve de
forma unica. No es una especificacion ejecutable ni autoriza que Cloud Run
rellene un valor por inferencia. Cada regla debe ser validada por Operaciones y
su decision debe indicar responsable, fecha, ejemplos y excepciones.
Una vez aprobada, cada regla debe convertirse en una entrada versionada de
cloud-run/reference-data/reglas_operativas.json y en pruebas automáticas antes
de habilitar su uso en PARA_PROCESAR.

Como validar cada regla
-----------------------
1. Marcar una sola decision aprobada.
2. Indicar el sistema o documento que tiene prioridad cuando las fuentes se
   contradicen.
3. Definir que debe hacer el flujo si faltan datos o persiste el conflicto:
   detener para revision, dejar en blanco o aplicar una regla explicita.
4. Conservar al menos dos PDFs anonimizados que cubran el caso normal y la
   excepcion. Esos casos se convertiran en pruebas automaticas antes de cambiar
   el codigo.

4. TIPO DE INMUEBLE Y VALOR A REPORTAR
--------------------------------------
Campos afectados: TIPO_INMUEBLE, TIPO_INMUEBLE_COD, MONEDA_COD y VALOR.

El catalogo actual contempla CASA y DEPARTAMENTO. Los informes pueden incluir
cocheras, depositos u otros componentes junto con el inmueble principal. Para
un departamento el extractor prioriza el valor comercial. Para una casa toma
el valor de reconstruccion, mientras que el catalogo de integración denomina la
opcion de casa como "VALOR NUEVO". Esta equivalencia requiere confirmacion
formal antes de usarse en casos productivos de casas.

Preguntas para Operaciones:
- Que tipo y valor se reportan si un mismo PDF incluye departamento, cochera y
  deposito?
- Debe generarse una fila por unidad o solo por la garantia principal?
- "Valor de reconstruccion" satisface el campo que el catálogo denomina
  "VALOR NUEVO" para una casa?
- Que hacer con tipos no presentes en el catalogo?

5. ANO DE CONSTRUCCION Y EDAD EFECTIVA
--------------------------------------
Campos afectados: ANO, EDAD_EFECTIVA y ORIGEN_ANO.

Regla tecnica vigente: se usa el ano de construccion explicito. Solo si no se
encuentra, se calcula ANO = ano de expedicion - edad efectiva numerica. Si la
edad indica "En construccion" u otro texto no numerico, no se realiza una
resta inventada.

Preguntas para Operaciones:
- Esta regla coincide con la operativa en todos los tipos de tasacion?
- Como se debe tratar edad 0, "En construccion", rangos de edad o anos de
remodelacion?
- Si el calculo genera un ano improbable, se bloquea la fila o se solicita
correccion manual?

ACTUALIZACION OPERATIVA - 2026-10-05
-------------------------------------
El procesamiento historico de D01, D02, D03 y D04 fue autorizado como base
para la implementacion activa. Las decisiones se versionaron en
cloud-run/reference-data/reglas_operativas.json y se prueban con PDFs
sinteticos.

Regla | Decision implementada | Casos de referencia

PRESTAMO y SEGURO INMUEBLE | Cloud Run los deja vacios; PAD/IBM 3270 los obtiene y registra despues. | D01-D04.
